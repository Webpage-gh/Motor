# motor —— 最小马达调用库

> Redmi Note 11 (`evergo`) / AWINIC **AW8697** LRA / `/dev/input/event2`。
> 一个 C 文件 + 一条编译命令，能直接把任意 8bit PCM 喂给马达。
> **必须 root**（`/dev/input/event2` 与 sysfs 都只有 root 可写）。

## 1. 30 秒上手

```bash
cd ~/motor
./build.sh                                  # 产出 ./motor

su -c '~/motor/motor tone 600 1000 60'      # 600Hz 响 1 秒
su -c '~/motor/motor play ~/xxx.bin 0x5FFF' # 播一段 PCM
su -c '~/motor/motor stop'                  # 立即静音
```

> Termux 里 `su -c` 内是 `/system/bin/sh`，**不会展开 `~`**，
> 所以给 `su` 的路径要写全：`/data/data/com.termux/files/home/motor/motor`。

### 放整首歌（一条命令）

```bash
./mplay.sh 歌.mp3                 # 从头放
./mplay.sh 歌.mp3 30 60           # 30s 起放 60 秒
./mplay.sh 歌.mp3 30 60 0x5FFF    # 再加音量档
./mplay.sh --dry 歌.mp3 30 10     # 只体检，不振动（普通用户可跑）

```

手写等价于：

```bash
ffmpeg -v error -ss 30 -t 60 -i 歌.mp3 -af "afade=t=in:st=0:d=0.02,afade=t=out:st=59.98:d=0.02" \
       -f f32le -ac 1 -ar 24000 - | su -c 'motor/motor stdin'
```

`stdin` 会**先把整段读完再开始振**（安全层要总剂量才能决定放不放）：

| 长度 | 读取缓冲 | 起播延迟 |
|---|---|---|
| 30 s | 3 MB | <1 s |
| 60 s | 6 MB | ~1 s |
| 300 s | 29 MB | ~4 s |

`motor stdin` 自己做：降混已是 ffmpeg 完成 → **8bit 量化带 ±1 LSB 三角抖动**（比原来
`int16→s8` 截断的噪声底干净）→ 安全层 → 播放。不再产生中间 `.bin`。

> 音量就是源文件的音量：**不做峰值归一化**。曾有过 `--norm`（纯峰值归一到 0.9），
> 实测人声素材会被放大 3 倍、把 190–485Hz 自由区推到“危险振动”，已删除（见 git `71f83b4`）。

### 提取主旋律（原曲 → 单声部）

```bash
./tools/extract 原曲.mp3 lead.flac     # 输出后缀 .flac/.wav 无损，.mp3 走 320k
./mplay.sh --dry lead.flac             # 体检
./mplay.sh lead.flac 30 60             # 播放
```

`tools/extract` 是 `tools/extract_lead.py` 的 C 移植（同一算法：STFT 谐波软掩码 +
原始相位 overlap-add，不合成、不改响度）。实测对拍：

| 输入 | Python | C | 一致性 |
|---|---|---|---|
| 20s 切片 | 5.8 s | 2.1 s | 相关 1.000000，最大差 4e-5（1 个 int16 LSB），−98 dB |
| 127s 全长 | ~25 s | **9.8 s** | 统计完全相同（77% 有音高、41~91 MIDI、峰值 0.8416） |

依赖只有 `ffmpeg`（解码/编码）和 `-lm`，不需要 numpy/scipy。

## 2. 库接口（只有 4 个函数）

```c
int  motor_open(void);                                       // 0 = 成功
int  motor_play(const signed char *pcm, size_t n, int mag);  // 阻塞播放，自动收尾
int  motor_tone(double hz, int ms, int peak, int mag);       // 内置正弦
void motor_stop(void);                                        // 立即静音
```

- `pcm`：**8bit 有符号、单声道、24000 Hz**（1 秒 = 24000 字节）
- `peak`：样本峰值 0~127
- `mag`：`0x7FFF` = 100%，`0x5FFF` = 50%，`0x3FFF` ≈ 25%（见 §4）

## 3. 协议（踩了三天坑才通的唯一正门）

```
1) ioctl(EVIOCSFF, FF_PERIODIC)
     .u.periodic.waveform    = FF_CUSTOM (0x5d)   ← 设备 ffbit 里没有 FF_SINE，
     .u.periodic.custom_len  = 2                     用 FF_SINE/FF_SQUARE 一律 EINVAL
     .u.periodic.custom_data = {197, 0, 0, 0}     ← 197 = CUSTOME_WAVE_ID，进流式通路
     .u.periodic.magnitude   = mag                ← 等价 vmax，就是"全局音量"
2) write(/dev/input/event2, {EV_FF, id, 1})       ← 开播
3) open 写 /sys/.../9-005a/custom_wave，每 512 字节 write() 一次（写满会阻塞，不丢数据）
4) 轮询读 custom_wave 的 free_size，回到 max_size(8192) 才算播完
5) 立刻再写 8×512 字节零（≈171ms 静音尾巴）
6) 收尾：EV_FF stop → EVIOCRMFF → 重新上传 periodic(197) 让内核 rb_init() 清索引
        → 上传并撤销一个 FF_CONSTANT（清 is_custom_wave）→ activate=0, activate_mode=0
```

**第 6 步不能省**：跳过它，驱动会留在半播状态，之后所有播放都会出现
"共振 + 混乱高频"（芯片里残留的旧数据被冲出来）。

## 4. 音量 `mag` → 驱动 `level`

| mag | level | 相对音量 |
|---|---|---|
| `0x7FFF` | `0x80` | 100% |
| `0x5FFF` | 64 | 50% |
| `0x3FFF` | `0x1E` | ~23% |

换算：`level = (mag - 16383) / 128`，`mag >= 0x7FFF` 取 `0x80`，`<= 0x3FFF` 取 `0x1E`。
`mag` 只影响振幅，**不影响芯片内部 F0 与波形**。

## 5. 内置安全层（自动，默认开启）

`motor_play()` / `motor_tone()` 在**上传前**自动对 PCM 做一遍处理，规则全部来自实测：

| 检查 | 规则 | 触发后 |
|---|---|---|
| 共振带 | 152~190Hz / 485~581Hz 的安全峰值表 | 逐块测量，把该段按比例压下去（平滑过渡，不产生新陡边） |
| 档位放宽 | 低档位按 `×128/level` 线性放宽 | `0x5FFF` 时允许值翻倍 |
| 带内余量 | **按带分开**：152–190Hz `×0.03`、485–581Hz `×1.00`（带外不乘）。见下方“带内余量系数” | — |
| RMS | **按 2048 样本分块判**：带内 ≤ 15，带外 ≤ 90（= peak 127） | 块内缩放 + 块间过渡。带外不用 15 压：实测表允许满幅，压到 peak 21 属误伤 |
| 瞬态 | 每样本跳变 ≤ max(40, **3×**前视 64 样本局部 RMS) | 压该段增益（腐蚀提前下压 + 平滑恢复）：满幅 click 127 → 40 |
| 能量预算 | `剂量 = Σ rms²·dt > 121500`（≈满幅 15s）或 `>300s` | **事前拒绝播放**（退出码 3），设备一个字节都不写；`--force` 绕过，`--max-ms` 截短 |

**带内余量系数（听感定标，`motor.c` 顶部 `HEAD_B1`/`HEAD_B2`）**

| 系数 | 取值 | 效果 | 依据 |
|---|---|---|---|
| `HEAD_B1`（152–190Hz） | **0.03** | 只剩“低音”级的残余，不再“敲壳” | 放音乐时该带只贡献“闷的敲壳感”：0.25 仍偏闷、0.03 高低频最均衡，但**不是砍废**——听感上仍有安全强度的低频 |
| `HEAD_B2`（485–581Hz） | **1.00** | 直接用实测表值（540Hz → 18） | 再乘 0.8 会让高频段发虚 |

编译期可覆盖，做对比实验不用改代码：

```bash
clang -O2 -DHEAD_B1=0.8 -DHEAD_B2=0.8 -o motor motor.c -lm   # 早前行为
clang -O2 -DHEAD_B1=0.25 -o motor motor.c -lm                # 中间档
```

**它到底压掉了什么（实测，200 段主旋律提取版）**

| | 152–190 | 190–485 | 485–581 | >581 |
|---|---|---|---|---|
| 输入 | 0.07% | 1.7% | 0.80% | 96.8% |
| 经安全层 | 0.03% | 1.7% | 0.81% | 96.9% |

- 该带能量本来就极小（0.07%），`HEAD_B1=0.03` 只是把极少数“敲壳”尖峰按下去；
- **低音听感来自 190–485Hz 自由区**（一点没压，上限满幅 127）以及 >581Hz 的机身发声；
- 所以 0.03 是“去掉闷振、低频还在”，不是“砍掉低音”。
- 例外：若素材的音高本身就落在 165–190Hz（如低音旋律），那它会被明显压小；要故意用这段做触觉，调高 `HEAD_B1` 或 `--no-safety`。

实测校验（`motor check`，不播放）：

```
170Hz 满幅 0x7FFF → 共振带 170Hz 压到 1%（HEAD_B1=0.03 的直接结果）
170Hz 满幅 0x5FFF → 共振带 170Hz 压到 2%                       ← 档位放宽生效
540Hz 满幅 0x7FFF → 共振带 539Hz 压到 15%
540Hz 满幅 0x5FFF → 共振带 539Hz 压到 29%，RMS 25.4 → ×0.59
600Hz 满幅 127 / 300ms → 通过 (RMS 90.0, 最大跳变 20)    ← 带外放行
600Hz 300ms peak 100     → 通过（此前被 RMS 15 压到 peak 21）
满幅单样本 click     → 瞬态压到 31%（跳变 127 → 40）
0.5s 满幅 300Hz + 59.5s 静音 → RMS 88.7 → ×0.20（分块判才抓得到；
                                     另报「170Hz 压到 25%」= 突发突然停止的 click 泄漏）
300Hz 正弦 peak 15   → 通过 (RMS 10.7, 最大跳变 2)          ← 正弦不误伤
`--max-ms 1000` 的 8s 文件 → 长度 8.00s → 1.00s（真截断）
```

```bash
motor check <file.bin> [mag]      # 只体检，不振动（不需要 root）
motor sweep <f0> <f1> <ms> [peak] [mag] [lin]   # 扫频，默认对数
motor --dry sweep 40 1200 4000   # 扫频只体检（普通用户可跑）
motor --max-ms 5000 play ...      # 真正截断到 5 秒（非负整数，非法值报错退出）
motor --force play long.bin       # 绕过能量预算/时长上限（超量时才需要）
motor --no-safety play ...        # 跳过安全层（不建议）
```

**扫频 `sweep`**

```bash
motor sweep 40 1200 4000          # 40→1200Hz，4 秒，对数（每倍频程等时）
motor sweep 1200 40 4000 60       # 反向扫频，峰值 60
motor sweep 200 1000 4000 100 lin # 线性扫频（等 Hz/秒）
```

- 对数默认：低频段停留更久，探共振/听死角更公平；线性适合找某一窄带；
- 自带 20ms 起落，不会因为切口产生 click；
- **同样过安全层**：扫过 152–190 / 485–581 时会被自动压制（这是特性不是 bug，
  想听“未处理的原始扫频”得加 `--no-safety`，但那会真的撞共振带）。

**健壮性约定**

- 安全检查内存不足时 **`motor_play()` 返回 -2 并拒绝播放**（不会"放行未检查的内容"）
- 瞬态限幅用 `float`，3 条缓冲共 `3×4×n` 字节（22s ≈ 6.0MB）
- 报告拼接有长度钳制，不会栈溢出

**已知行为**：>600Hz 的满幅内容若跳变超过 3×局部 RMS，会被瞬态规则连带压下去
（判据放宽到 3× 之后，8kHz/峰值60 实测已"通过"，不再被压；只有真正陡的瞬态才压）。
这条优先于"带外一律 127"，因为高频满幅本身就是嗡嗡声而不是振动。

能量预算为什么是"事前拒绝"而不是"越放越小声"：剂量在预处理里一次算完，
超了直接不播（`退出码 3`），所以不会出现"响一段突然变弱"；想放长就用

## 6. 安全三条（血泪，写给写波形的人）

1. **只用正弦**。方波/锯齿的陡边是宽频激励，会撞壳。
2. **避开共振带**：`152~190Hz` 与 `485~581Hz` 是机身共振区，满档安全峰值分别只有
   `31`（170Hz）和 `18`（540Hz）。安全层默认再乘 `HEAD_B1=0.03` / `HEAD_B2=1.00`，
   所以 152–190Hz 实际只剩 ~1%，485–581Hz 剩 ~15%；不压就是"敲壳"。
3. **带内**别超 RMS 15（满幅 170Hz 持续正弦会撞限位）；**带外**按实测表可到
   peak 127，RMS 上限随之放到 90。
4. **别用 click 当鼓点**。安全层会把单个满幅跳变压到 40，但连续瞬态依旧是宽频激励。

单次播放建议 ≤5 秒；长音频先切片。

**响度天花板在共振带，不在 `mag`**

实测（主旋律提取版，10s，`mag=0x7FFF`）：

| 版本 | 8bit 峰值 | RMS | 安全层反应 | 实际响度 |
|---|---|---|---|---|
| 原始（peak 0.426） | 54 | 12.4 | 通过 | 基准 |
| 归一化到 0.9（+6dB） | 107 | 24.8 | 共振带 539Hz 压到 87%、RMS→×0.59 | 仅 **+1.4dB** |

原因：这类主旋律本身就有大量能量落在 485–581Hz，音量一抬就撞“带内 RMS ≤15”，
被压回去。**想要更响，只能改 `HEAD_B2`（有风险）或移调避开该带（牺牲音准）**，
靠增益或 `mag` 加大是撞墙。

## 7. 听感定标记录（A/B 实测，手机机身，非耳机）

| 实验 | 结论 |
|---|---|
| 主旋律提取版原样播放（无压缩、8bit/24k） | 与耳机听感“几乎没区别”，**不需要压缩器** |
| `<400Hz` 衰减 0% / 25% / 50% / 100% | 0%＝不震动只发声；**25%＝微震，听感最佳**；50%＝振动更强；100%＝振动干扰听感 |
| `<152Hz` 高速高通（两级 150Hz） | 去掉“偶发闷振动”（低频突刺，实测 6s 处占该帧 98%） |
| `HEAD_B1` 0.8 → 0.25 → 0.03 | 0.03 高低频最均衡；**仍保留安全强度的低频**，不是砍废 |
| 掩码下限 20 → 6Hz（提取脚本） | 20 秒盲测**听不出区别** → 不做此改动 |
| +6dB 增益 | 略响、无共振（剂量仍只占 15% 预算）→ **曾做成 `--norm`，已删除**：人声素材实测“危险共振” |

## 8. 高频的事实

马达**不是扬声器**：>600Hz 它能"发声"（靠机身声学共振，2.4kHz 最响），
但多声部/宽频带内容只会变成"坏掉的手机"。可用的只有：
单声部纯音（能听出旋律）、低频包络（能摸到节奏）、瞬态（鼓点）。
