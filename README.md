# motor

用 **Redmi Note 11 (`evergo`) / AWINIC AW8697 LRA** 当振动器播放音频的极简库 + 命令行工具。
一个 C 文件，一条编译命令，能直接把任意 8bit PCM 喂给马达；内置一层基于实测的安全层，
把"会撞壳/会发热"的内容挡住。

> **仅限自担风险自用。** 这层安全措施来自单台设备的实测，不是厂商规格；
> 它能让"听起来像耳机"的素材安全播放，但**不能保证任何素材都不损伤马达**。

## 能做什么

马达不是扬声器，能"发声"靠的是机身结构共振。实际可用的只有三类内容：

| 内容 | 效果 |
|---|---|
| 单声部纯音 / 主旋律 | 能听出旋律（`支持40–11700Hz`） |
| 低频包络 | 能摸到节奏 |
| 瞬态 | 鼓点，但连续瞬态会被安全层压 |

多声部/宽频带原曲直接播放只会变成"坏掉的手机"。本仓库因此包含两步：

```
原曲.mp3 ──extract──> lead.flac ──mplay.sh──> 马达
          （多声部→单声部）              （解码+量化+安全层+播放）
```

## 如何使用

要求：Termux、`clang`、`ffmpeg`、**root**（`su` 可用于访问 `/dev/input/event2`）。

### 1. 编译
```bash
pkg install clang ffmpeg
git clone <this repo> ~/motor && cd ~/motor
./build.sh
```

做的事：编译src目录下的extract.c和motor.c到项目根目录。

### 2. 做扫频测试
```bash
# <f0> <f1> <ms> [peak]
su -c ./motor sweep 40 11700 10000 30
```

确认无共振异响后，可以逐渐提高peak，不指定peak则为最大值100。

### 3. 提取主旋律（无需Root）

```bash
./extract 原曲.mp3 lead.flac     # 输出 .flac/.wav 走无损，.mp3 走 320k
```

做的事：STFT 上按估计的 f0 做**谐波软掩码**，用**原始相位** overlap-add 重建。
不重新发声、不改音色/响度/包络/时间轴/声道，只保留"主旋律所在的那几条谱线"。

### 4. 检测主旋律（可选，无需Root）

```bash
./mplay.sh --dry lead.flac 30 10       # 只看报告
```

### 5. 播放（需Root，必须先做扫频测试）

```bash
# 从头放
./mplay.sh lead.flac
# 30s 起放 60 秒
./mplay.sh lead.flac 30 60
# 再加上调整音量（相对于满音量 0x7FFF 的 50%）
./mplay.sh lead.flac 30 60 0x5FFF
```

`mplay.sh` 做的核心工作如下：

```bash
ffmpeg -v error -ss 30 -t 60 -i lead.flac \
       -af "afade=t=in:st=0:d=0.02,afade=t=out:st=59.98:d=0.02" \
       -f f32le -ac 1 -ar 24000 - | su -c "$PWD/motor stdin"
```

- `ffmpeg` 用普通用户跑，只有 `motor` 那一段需要 root，脚本自动使用 su 执行这一部分；
- 8bit 量化带 **±1 LSB 三角抖动**（抖动量化为白噪声，不是截断）；
- 不做归一化、不做压缩，**源文件多响就多响**；
- 切口自动加 20ms 淡入淡出，避免切口陡边被瞬态规则误伤。

`motor stdin` 会**先把整段读完再开始振**（安全层需要总剂量才能决定放不放）：

| 长度 | 读取缓冲 | 起播延迟 |
|---|---|---|
| 30 s | 3 MB | <1 s |
| 60 s | 6 MB | ~1 s |
| 300 s | 29 MB | ~4 s |

## 命令参考

```bash
motor tone <Hz> <ms> [peak] [mag]        内置正弦（默认 peak 60，20ms 起落）
motor play <file.bin> [mag]              播放 8bit 有符号单声道 24kHz PCM，普通音频很容易炸
motor check <file.bin> [mag]             只做安全体检（不需 root）
motor sweep <f0> <f1> <ms> [peak] [mag] [lin]
                                         扫频，默认对数；加 lin 为线性
motor stdin [mag]                        管道读 f32le 单声道 24kHz 并播放
motor stop                               立即静音（紧急用，不做收尾）
```

前置选项（写在命令**之前**，可组合）：

| 选项 | 作用 |
|---|---|
| `--dry` | 只体检不播放（配合 `sweep` / `stdin`） |
| `--max-ms N` | 真正截断到 N 毫秒，尾部清零 |
| `--no-safety` | 跳过安全层（不建议） |
| `--force` | 绕过能量预算/时长上限（超剂量时才需要） |

```bash
motor --dry sweep 40 1200 4000    # 扫一下哪些频率能摸到
motor --max-ms 5000 play x.bin     # 只放前 5 秒
```

`mplay.sh`：

```bash
mplay.sh <文件> [起始秒] [时长秒] [mag]
mplay.sh --dry <文件> ...
```

## 安全层

`motor_play()` 在**上传前**就地处理 PCM，按这个顺序：

| 步骤 | 规则 | 说明 |
|---|---|---|
| 1. 截断 | `--max-ms N` | 真截断 + 尾部清零 |
| 2. 高通 | 25Hz 二级 | 去直流与 <40Hz（常数输入会被压到 0） |
| 3. 共振带 | 152–190Hz / 485–581Hz 峰值表 | 逐块测幅度，按比例压，块间线性过渡 |
| 4. 档位放宽 | `×128/level` | 低音量档允许更大峰值（`0x5FFF` 时翻倍） |
| 5. 带内余量 | `HEAD_B1=0.03` / `HEAD_B2=1.00` | 两段共振带分开给余量；带外不乘 |
| 6. RMS | 分块 2048：带内 ≤ 15，带外 ≤ 90 | 必须分块（整段会被长静音稀释）；带外不用 15 压，会误伤厂商素材 |
| 7. 预算 | 剂量 `Σ rms²·dt ≤ 121500` 且 `≤ 300s` | 超了**事前拒绝**（退出码 3），一个字节都不写；`--force` 绕过 |
| 8. 瞬态 | 每样本跳变 ≤ `max(40, 3×前视局部RMS)` | 满幅 click 127 → 40；3× 才不会误杀高频正弦 |

**为什么是"事前拒绝"而不是"越放越小声"**：剂量在预处理里一次算完，超了直接不播，
不会出现"响一段突然变弱"。想放长就用 `--max-ms` 截到预算内。

剂量预算换算（`T ≤ 121500 / RMS²`）：

| 内容 RMS | 可放时长 |
|---|---|
| 30 | ~135 s |
| 28 | ~155 s |
| 20 | 撞 300s 硬上限 |
| 12 | 撞 300s 硬上限 |

共振带的安全峰值（满档 `mag=0x7FFF`，实测）：

| 频率 | 允许峰值 | 占比 |
|---|---|---|
| 170 Hz | 31 | 24% |
| 540 Hz | 18 | 14% |
| 300 Hz | 127 | 100%（带外，自由区） |
| 600 Hz | 127 | 100%（带外） |

原始记录见 `reference/频率-振幅测试表.csv`（27 行，与代码里 `SAFE[]` 的 25 个点逐一对应）。

`HEAD_B1=0.03` 会让 152–190Hz 再降到 ~1%（只剩"敲壳"尖峰被按掉）；
`HEAD_B2=1.00` 表示 485–581Hz 直接用表值，不额外打折。
两段都是编译期常量，可做对比实验：

```bash
clang -O2 -DHEAD_B1=0.25 -o motor src/motor.c -lm    # 中间档
clang -O2 -DHEAD_B1=0.8 -DHEAD_B2=0.8 -o motor src/motor.c -lm  # 早期行为
```

**响度天花板在共振带，不在 `mag`。** 实测主旋律素材（10s，满档）：

| 版本 | 峰值 | RMS | 安全层反应 | 实际响度 |
|---|---|---|---|---|
| 原始（peak 0.43） | 54 | 12.4 | 通过 | 基准 |
| 归一化到 0.9（+6dB） | 107 | 24.8 | 539Hz 压 87%、RMS→×0.59 | 仅 +1.4dB |

曾因此加了 `--norm`（纯峰值归一化），后来在**人声素材**上实测出"危险共振"——
峰值归一化不看能量落在哪个频段，会把 190–485Hz 自由区整体放大 3 倍。**该功能已删除**
（需要时可从 git 历史 `71f83b4` 取回，但别用在人声上）。

## 音量 `mag` → 驱动 `level`

| `mag` | `level` | 相对音量 |
|---|---|---|
| `0x7FFF`（默认） | `0x80` | **100%** |
| `0x5FFF` | 64 | 50% |
| `0x4FFF` | 32 | 25% |
| `0x3FFF` | `0x1E` | ~23%（下限） |

换算：`level = (mag - 16383) / 128`，上限 `0x80`、下限 `0x1E`。
`mag` 只改振幅，**不改芯片内部 F0 与波形**。默认已是最大，**没有上调空间**。

## 库接口

```c
int  motor_open(void);                                       // 0 = 成功
int  motor_play(const signed char *pcm, size_t n, int mag);  // 阻塞播放，自动收尾
int  motor_tone(double hz, int ms, int peak, int mag);       // 内置正弦
void motor_stop(void);                                       // 立即静音
```

- `pcm`：**8bit 有符号、单声道、24000 Hz**（1 秒 = 24000 字节）
- `motor_play()` 返回 `0` 成功、`-1` 设备错误、`-2` 安全检查失败（内存不足）并拒绝播放、
  `-3` 超能量预算/时长并拒绝播放
- 返回值 < 0 时**不会**往设备写任何东西

## 协议

AW8697 的流式 PCM 通路只有一个正门（踩了很久才通）：

```
1) ioctl(EVIOCSFF, FF_PERIODIC)
     .u.periodic.waveform    = FF_CUSTOM (0x5d)     ← 设备 ffbit 里没有 FF_SINE，
     .u.periodic.custom_len  = 2                       用 FF_SINE/FF_SQUARE 一律 EINVAL
     .u.periodic.custom_data = {197, 0, 0, 0}       ← 197 = CUSTOME_WAVE_ID，进流式通路
     .u.periodic.magnitude   = mag                  ← 等价 vmax，就是"全局音量"
2) write(/dev/input/event2, {EV_FF, id, 1})         ← 开播
3) open 写 /sys/.../9-005a/custom_wave，每 512 字节 write()（写满会阻塞，不丢数据）
4) 轮询读 custom_wave 的 free_size，回到 max_size(8192) 才算真正播完
5) 立刻再写 8×512 字节零（≈171ms 静音尾巴），让停止落在静音里
6) 收尾：EV_FF stop → EVIOCRMFF → 重新上传 periodic(197) 让内核 rb_init() 清索引
        → 上传并撤销一个 FF_CONSTANT（清 is_custom_wave）→ activate=0, activate_mode=0
```

**第 6 步不能省。** 跳过它，驱动会留在半播状态，之后所有播放都会变成
"共振 + 混乱高频"（芯片里的残留数据被冲出来）。

设备节点：`/dev/input/event2`；
sysfs：`/sys/devices/platform/11d01000.i2c9/i2c-9/9-005a/`。

## 实测数据

**C 提取器 vs Python 参考实现**（同一输入，逐样本对拍）：

| 输入 | Python | C | 一致性 |
|---|---|---|---|
| 20s 切片 | 5.8 s | **2.1 s** | 相关 1.000000，最大差 4e-5（1 个 int16 LSB），−98 dB |
| 127s 全长 | ~25 s | **9.8 s** | 统计完全相同（77% 有音高、41–91 MIDI、峰值 0.8416） |

**安全层自检**（`motor --dry check`，可直接复现）：

```
170Hz 满幅 0x7FFF      → 共振带 170Hz 压到 1%
170Hz 满幅 0x5FFF      → 共振带 170Hz 压到 2%          ← 档位放宽生效
540Hz 满幅 0x7FFF      → 共振带 539Hz 压到 15%
540Hz 满幅 0x5FFF      → 共振带 539Hz 压到 29%，RMS 25.4 → ×0.59
300Hz 满幅 1s          → 通过 (RMS 88.7, 最大跳变 11)   ← 带外放行
300Hz peak 15          → 通过 (RMS 10.6, 最大跳变 3)    ← 正弦不误伤
0.5s 300Hz + 59.5s 静音 → RMS 88.7 → ×0.20             ← 分块判才抓得到
满幅单样本 click        → 瞬态压到 31%（跳变 127 → 40）
常数 10 的直流文件       → 通过 (RMS 1.4)，输入已被高通清零
8kHz peak 60           → 通过（3× 判据下不再被压）
--max-ms 1000 的 8s 文件 → 8.00s → 1.00s（真截断）
```

**听感定标**（同一台手机机身，非耳机，A/B 实测）：

| 实验 | 结论 |
|---|---|
| 提取版原样播放（无压缩） | 与耳机听感"几乎没区别"，**不需要压缩器** |
| `<400Hz` 衰减 0/25/50/100% | 0%＝只发声不震；**25%＝微震，听感最佳**；100%＝振动干扰听感 |
| `<152Hz` 两级 150Hz 高通 | 去掉"偶发闷振动"（低频突刺） |
| `HEAD_B1` 0.8 → 0.25 → 0.03 | 0.03 高低频最均衡，**仍保留安全强度的低频**，不是砍废 |
| 提取掩码下限 20 → 6Hz | 20 秒盲测**听不出区别** → 不做此改动 |

盲测结论：**无提示时人耳检出率只有 25%**（误报 0）。所以本仓库的验收靠
"合成集准确率 + 逐样本对拍"，听感只用来判断"能不能用"，不用来判断"对不对"。

## 已知限制

- **只管 152–581Hz 两个共振带**；>581Hz 靠机身声学共振发声（2.4kHz 最响），安全层不建模；
- **发热由能量预算控制**，不测温度：长时间播放只给提示，不强制中断；
- **不检测多声部**：原曲必须先用 `extract` 提取，否则就是宽频激励；
- 长内容靠 `--max-ms` 切段，不支持"边放边算"的流式剂量；
- 只有 8bit / 24kHz 一种 PCM 格式（芯片流式通路就是这个采样率）。
